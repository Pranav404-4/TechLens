# TechLens — Browser Technology Detector

TechLens is a passive browser extension that identifies website technologies using browser-visible evidence, including page elements, resource URLs, and HTTP response headers where browser permissions allow.

It provides technology detections with confidence levels and a Security Insights panel that highlights selected security-header configurations and potential hardening opportunities.

TechLens is designed for **Chrome and Firefox** using Manifest V3.

> **Important:** TechLens performs passive, heuristic analysis. It does not exploit websites, scan ports, or provide a complete security audit.

## Features

### Technology Detection

TechLens examines accessible page evidence to identify technologies such as:

- **Frontend frameworks and libraries:** React, Vue.js, Angular, Svelte, jQuery
- **Frontend frameworks and styling:** Next.js, Nuxt, Bootstrap, Tailwind CSS
- **Content management and e-commerce:** WordPress, Drupal, Joomla, Shopify, Magento, and other supported platforms
- **Analytics and tag management:** Google Analytics, Google Tag Manager, Matomo, and other supported analytics tools
- **Backend and server indicators:** PHP, ASP.NET, Express/Node.js, Apache, Nginx, and other supported technologies
- **Hosting and infrastructure indicators:** Cloudflare, AWS, and other supported services

The technologies reported depend on the evidence available on the inspected page and the detection rules included in the current version.

### Detection Results

- Technology categories and filters
- Confidence levels for detected technologies
- Evidence-based detection rather than unsupported guesses
- Technology version reporting when reliable version information is available
- Refresh and rescan functionality

Confidence scores are heuristic indicators of the strength of the available evidence. They are not statistical probabilities.

### Security Insights

TechLens includes a Security Insights analyzer that examines selected HTTP response headers and reports potential security-configuration concerns.

Depending on the available headers, findings may include:

- Server and technology information disclosure
- Content Security Policy (CSP) configuration
- Potentially permissive script policies
- Frame protection
- HTTP Strict Transport Security (HSTS)
- MIME-sniffing protection
- Referrer Policy
- Permissions Policy
- Cross-origin isolation and resource-policy recommendations

Findings can include severity, descriptions, observed evidence, and recommendations.

TechLens also displays a **Security Priority score** based on its heuristic assessment of observed header findings.

**The score is not a probability that a website is vulnerable.** It does not represent a complete penetration test, vulnerability assessment, or overall security rating. Browser-visible headers provide only a limited view of a website's security.

A header that is not observed is not necessarily proof that the corresponding protection is absent in every part of the website.

### JSON Reports

TechLens supports two JSON exports:

1. **Technology Report** — includes scan information, detected technologies, and associated report details.
2. **Security Report** — includes Security Insights information, the priority score, summary information, findings, and report notes.

Export filenames include a website label and date. For example:

- `TechLens Report - github - 2026-10-29.json`
- `TechLens Security Report - github - 2026-10-29.json`

The actual website label and date depend on the page being inspected and the date generated by the extension.

## Installation

### Chrome

1. Obtain and extract the TechLens project folder.
2. Open `chrome://extensions`.
3. Enable **Developer mode**.
4. Click **Load unpacked**.
5. Select the project folder containing `manifest.json`.
6. Open a website and click the TechLens extension icon.

### Firefox

1. Obtain and extract the TechLens project folder.
2. Open `about:debugging#/runtime/this-firefox`.
3. Click **Load Temporary Add-on…**.
4. Select `manifest.firefox.json` from the project folder.
5. Open a website and click the TechLens extension icon.

Firefox temporary add-ons are generally removed when Firefox restarts. For distribution beyond local testing, follow Mozilla's extension packaging and signing requirements.

> **Firefox note:** The Firefox manifest uses `background.service_worker`. Verify compatibility with the Firefox version and configuration you intend to support before distributing the extension.

## Using TechLens

1. Open the website you want to inspect.
2. Click the TechLens toolbar icon.
3. Review the detected technologies and their confidence levels.
4. Use the available filters to explore detection categories.
5. Open Security Insights to review observed security-header findings and recommendations.
6. Use the appropriate export button to save a Technology Report or Security Report as JSON.

Results depend on the evidence visible to the extension during the scan. Some technologies may not be detected if their identifiers are hidden, unavailable, or not covered by the current rules.

## Permissions and Privacy

TechLens uses browser permissions to inspect the active website and collect evidence needed for technology detection and Security Insights.

The manifests include the following permissions:

- **`activeTab`** — grants access to the active tab following user interaction.
- **`scripting`** — allows the extension to execute inspection code where permitted.
- **`storage`** — provides browser storage access used by the extension.
- **`webRequest`** — supports observing relevant network request and response information where permitted.
- **Host permissions** — permit access to HTTP and HTTPS websites for the extension's intended inspection functions.

The main manifest also declares `tabs`, while the Firefox manifest does not.

TechLens uses passive fingerprinting techniques. It does not intentionally exploit websites or probe ports.

The extension's ability to inspect page data and response headers is limited by browser permissions, platform behavior, and cross-origin restrictions. Users should review the code and permissions before installing or distributing the extension.

Only inspect websites you are authorized to examine.

## Development and Testing

The project uses Node.js for JavaScript syntax checks and automated security-analyzer tests, with Prettier for formatting.

From the project directory, run:

### Run the security analyzer tests

```bash
node test-risk.js
```

### Check JavaScript syntax

```bash
node --check detector.js
node --check content.js
node --check background.js
node --check riskAnalyzer.js
node --check popup.js
node --check test-risk.js
```

### Check formatting

```bash
npx prettier --check detector.js content.js background.js riskAnalyzer.js popup.js test-risk.js
```

To format the JavaScript files if necessary:

```bash
npx prettier --write detector.js content.js background.js riskAnalyzer.js popup.js test-risk.js
```

Formatting changes should not be treated as proof of functional correctness. After modifying code, rerun the relevant tests and manually check the extension in the target browser.

## Limitations

- **Incomplete visibility:** Browser-visible evidence cannot reveal every technology or component running on a server.
- **Hidden or misleading headers:** Response headers can be omitted, rewritten, or generated by intermediaries such as CDNs and proxies.
- **Database detection:** Database engines generally cannot be identified reliably from ordinary page evidence. TechLens should not infer a database without a sufficiently reliable indicator.
- **Version detection:** A technology version may be unavailable even when the technology itself is detected.
- **Heuristic confidence:** Confidence scores describe the strength of detection evidence, not a statistical probability.
- **Security Insights scope:** Header-based findings cannot establish that a website is secure or vulnerable. They do not replace a professional security review.
- **Browser compatibility:** Manifest and background-processing behavior may differ between Chrome and Firefox and across browser versions.
- **Detection coverage:** Results depend on the rules implemented in the current release.
